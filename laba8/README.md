## **3. Теоретичні відомості**

### **3.1 Логування у розподілених системах**

Логування є обов’язковим елементом будь-якої розподіленої системи.
Логи дозволяють:

* аналізувати роботу сервісу,
* відслідковувати помилки,
* розуміти поведінку користувачів,
* проводити аудит роботи системи.

У мікросервісній архітектурі рекомендується передавати логи у **централізоване сховище** — наприклад, **Elasticsearch**.

### **3.2 Моніторинг**

Моніторинг — це безперервний процес відстеження стану системи.
Він включає:

* збір метрик,
* встановлення порогових значень,
* виявлення аномалій,
* оповіщення адміністраторів.

У даній роботі використовується **Prometheus**, який збирає дані з endpoint `/metrics` у форматі Prometheus Metrics Format.

### **3.3 Кастомні метрики**

Типи метрик:

* **Counter** — тільки зростає, напр. кількість запитів.
* **Gauge** — може збільшуватись і зменшуватись.
* **Histogram / Summary** — розподіл значень.

## **5. Опис реалізації**

### **5.1 Додавання змінних у код**

У код додано змінні:

```
prometheusPort = os.Getenv("PROMETHEUS_PORT")
logLevel = os.Getenv("LOG_LEVEL")
elasticURL = os.Getenv("ELASTIC_URL")
elasticIndex = os.Getenv("ELASTIC_INDEX")
```

### **5.2 Реалізація endpoint `/metrics`**

```
go func() {
	http.Handle("/metrics", promhttp.Handler())
	http.ListenAndServe(":"+prometheusPort, nil)
}()
```

### **5.3 Додавання кастомної метрики**

```
var commandsTotal = promauto.NewCounter(prometheus.CounterOpts{
	Name: "telegram_commands_total",
	Help: "Кількість виконаних команд",
})
```


### **5.4 Логування**

Змінна logLevel дозволяє перемикати рівень логування.

### **5.5 Відправка логів в Elasticsearch**

Використано простий HTTP-клієнт:

``` 
func sendToElastic(message string) {
	body := fmt.Sprintf(`{"timestamp":"%s", "message":"%s"}`,
		time.Now().Format(time.RFC3339), message)
	http.Post(elasticURL+"/"+elasticIndex+"/_doc", "application/json", strings.NewReader(body))
}
```

### Контральні Запитання 
Контрольні запитання та відповіді
1. Що таке метрика?

Метрика — це числовий показник, який відображає певний стан або характеристику роботи системи.
Вона використовується для моніторингу, аналізу продуктивності та виявлення проблем.

Приклади:

кількість запитів за секунду,

використання оперативної пам’яті,

час відповіді сервісу,

кількість помилок.

2. Які метрики найчастіше використовують у розподілених системах?

Найпоширеніші групи метрик:

Метрики продуктивності (Performance):

latency (затримка),

throughput (пропускна здатність),

час обробки запиту.

Метрики ресурсів:

CPU usage,

memory usage,

disk I/O,

мережевий трафік.

Бізнес-метрики:

кількість нових користувачів,

транзакції,

дії клієнтів.

Метрики надійності:

uptime,

кількість помилок / статус-коди.

Кастомні метрики:

кількість оброблених повідомлень,

кількість логінів,

кількість виконаних команд у боті.

3. Як працює Prometheus?

Prometheus працює за принципом pull-моделі:

Сервіси публікують метрики на endpoint, зазвичай /metrics.

Prometheus за розкладом опитує (pull) ці endpoints.

Зібрані метрики зберігаються у власну time-series базу даних.

На основі метрик можна:

будувати графіки,

встановлювати алерти,

аналізувати поведінку системи.

4. Для чого потрібен Grafana?

Grafana — це платформа для:

візуалізації метрик,

створення дашбордів,

аналітики системи в реальному часі,

налаштування alert-сповіщень.

Grafana використовується разом з Prometheus для зручного відображення усіх метрик у графічному вигляді.

5. Що таке централізоване логування?

Централізоване логування — це підхід, коли логи з усіх мікросервісів збираються у єдине сховище, де їх можна:

шукати,

фільтрувати,

аналізувати,

будувати звіти,

відслідковувати помилки.

Такий підхід критично важливий у розподілених системах, де без централізації знайти проблему майже неможливо.

6. Які переваги ELK Stack?

ELK = Elasticsearch + Logstash + Kibana

Переваги:

Пошук по логах у реальному часі
Elasticsearch — дуже швидка база для пошуку.

Гнучка обробка й трансформація логів
Logstash може фільтрувати, змінювати, парсити логи.

Зручна візуалізація та аналітика
Kibana дозволяє будувати графіки, таблиці, heatmap-и, dashboards.

Масштабованість
Підтримка великих обсягів log data.

Підтримка будь-яких форматів логів
JSON, текстові файли, структуровані та неструктуровані дані.

Підходить для мікросервісів і Kubernetes

7. Як організувати моніторинг мікросервісів у Kubernetes?

Моніторинг у Kubernetes зазвичай організовують так:

Prometheus Operator
– автоматично збирає метрики з подів, нод і сервісів.
– створює ServiceMonitor для вибірки даних.

Node Exporter
– збирає метрики з фізичних та віртуальних нод.

kube-state-metrics
– збирає інформацію про деплойменти, поди, сервісні об’єкти.

Grafana
– використовують для створення дашбордів.

Alertmanager
– система сповіщень про відмови або аномалії.

Sidecar-контейнери для логів або Fluentd/FluentBit
– пересилають логи в централізоване сховище (ELK, Loki, Cloud).
