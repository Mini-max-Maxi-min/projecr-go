 
# **ЛАБОРАТОРНА РОБОТА №4**

**Тема:** Технологічна архітектура

## **Мета роботи**

Розробити схему технологічного забезпечення РПС, описати інфраструктуру, технологічний стек, способи розгортання, мережеву взаємодію та забезпечення стійкості.

 

## **1. Теоретичні відомості**

Технологічна архітектура визначає, на яких платформах і в яких середовищах виконуються компоненти РПС.

**Основні елементи:**

* Контейнери (Docker, Podman) — упаковка застосунку з усіма залежностями.
* Оркестратори (Kubernetes) — управління контейнерами, балансування навантаження, моніторинг стану, автоматичне відновлення.
* Рівні архітектури:

  1. **Інфраструктурний** — сервери, мережеве обладнання, системи зберігання даних.
  2. **Платформний** — середовище виконання, бази даних, моніторинг.
  3. **Рівень застосунків** — мікросервіси, API-шлюзи, системи кешування.
  4. **Рівень доступу користувачів** — веб, мобільні додатки, API інтеграції.

**Приклади компонентів:**

* Бази даних: PostgreSQL, TimescaleDB, MongoDB.
* Кешування: Redis, Memcached.
* Балансування навантаження: NGINX, HAProxy, Ingress Controller.
* Спостережуваність: Prometheus, Grafana, ELK Stack.
* Безпека: аутентифікація/авторизація (OAuth 2.0, JWT), TLS/HTTPS, RBAC.
* Стратегії розгортання: rolling update, blue-green deployment, canary release.

 
## **2. Завдання до роботи**

1. Обрати стек технологій (наприклад, Node.js + PostgreSQL + Docker + Kubernetes).
2. Побудувати топологію розгортання у хмарі (AWS/GCP/Azure).
3. Описати способи забезпечення стійкості: load balancer, replica sets, autoscaling.

## **4. Контрольні запитання**
1. Що таке технологічна архітектура?
Технологічна архітектура — це опис того, на яких платформах, середовищах та інфраструктурі виконуються компоненти розподіленої системи. Вона визначає способи розгортання, взаємодію між сервісами, використання апаратних і програмних ресурсів, а також забезпечення масштабованості, стійкості та безпеки системи.

2. Які рівні архітектури розрізняють у РПС?

Інфраструктурний рівень — фізичні або віртуальні сервери, мережеве обладнання, системи зберігання даних.

Платформний рівень — середовище виконання (Docker, Kubernetes), бази даних, інструменти моніторингу.

Рівень застосунків — мікросервіси, API-шлюзи, кешування, служби авторизації.

Рівень доступу користувачів — веб-інтерфейси, мобільні додатки, API для інтеграцій.

3. Які типові компоненти включає інфраструктура розподіленої системи?

Сервери (фізичні або віртуальні)

Мережеве обладнання (маршрутизатори, комутатори)

Системи зберігання даних (SQL/NoSQL бази)

Балансувальники навантаження

Контейнери та платформи для їх оркестрації (Docker, Kubernetes)

Інструменти моніторингу та логування

4. Що таке контейнер і для чого його використовують?
Контейнер — це легковагова ізольована одиниця програмного забезпечення, яка містить застосунок та всі його залежності. Контейнери дозволяють:

запускати застосунки у будь-якому середовищі без конфліктів,

швидко розгортати та оновлювати сервіси,

забезпечувати ізоляцію та безпеку.

5. Як забезпечити масштабування у хмарному середовищі?

Вертикальне масштабування (scale up) — додавання ресурсів (CPU, RAM) існуючому серверу.

Горизонтальне масштабування (scale out) — додавання нових копій сервісів (replica sets).

Використання автоскейлінгу (autoscaling) для автоматичного збільшення/зменшення кількості вузлів або контейнерів у залежності від навантаження.

6. Яку роль відіграє балансувальник навантаження?
Балансувальник розподіляє вхідні запити між доступними сервісами або вузлами, щоб уникнути перевантаження окремого сервера і забезпечити високу доступність та стабільну роботу системи.

7. У чому переваги Kubernetes перед Docker Compose?

Автоматичне масштабування та відновлення контейнерів при збоях.

Балансування навантаження між репліками сервісів.

Оркестрація складних багатокомпонентних систем із декількома середовищами та namespaces.

Моніторинг стану контейнерів і автоматичне керування життєвим циклом.

Підтримка rolling updates, blue-green і canary деплойментів.
